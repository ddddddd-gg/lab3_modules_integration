# Сравнительный анализ стратегий интеграции

## Большой взрыв
Описание: все модули собираются и теструются, когда полностью готовы. Подходит для линейных задач.

Преимущества:
1. экономия время на ранних этапах
2. простота планирования
3. минимальные накладные расходы


Недостатки:
1. тяжелая отладка
2. позднее обнаружение архитектурных артефактов

## Нисходящая интеграция
Описание: Интеграция начинается с управляющих модулей верхнего уровня, для ненаписанных нижних модулей используются заглушки. Походит для веб-приложений и бизнес-систем.

Преимущества:
1. ранний рабочий прототип
2. простая локализация ошибок
3. гибкость архитектуры

Недостатки:
1. избыточный код заглушек
2. позднее тестирование критических алгоритмов
3. иллюзия готовности

## Восходящая стратегия
Описание: сборка начинается с самых низкоуровневых модулей, для их тестирования создается драйверы. Драйверы устройств, математические библиотеки.

Преимущества:
1. надежность ядра
2. простое нагрузочное тестирование


Недостатки:
1. высокая стоимость драйверов
2. риск пропуска глобальных ошибок

## Сэндвич-интеграция
Описание: разработка верхнего и ниженого слоя происходит параллельно и встречается на среднем слое интеграции. Подходит для крупных коммерческих систем и видеоигр.

Преимущества:
1. сбалансированное тестирование
2. высокое качетсво на стыке слоев
3. параллельная работ команд разработчиков

Недостатки:
1. сложность координации
2. двойные накладные расходы
3. высокие требования к архитектуре

## Риск-ориентированная стратегия
Описание: порядок интеграции диктуется картой рисков. Первыми собираются и тестируются модули, которые вызывают больше всего опасений. Может использоваться в медицинском и авиационном ПО, криптографических платформах.

Преимущества:
1. раннее предотвращение критических ошибок
2. эффективное распределние ресурсов

Недостатки:
1. высокие требования к аналитике
2. отсутствие видимого прогресса для бизнеса

## Функционально-ориентированная стратегия
Описание: система собирается сквозными пользовательскими сценариями и минимальный код всех модулей интегрируется сразу. Используется в коммерческих продуктах.

Преимущества:
1. простая расстановка приоритетов
2. видимый прогресс
3. готовность к релизу

Недостатки:
1. частый рефакторинг интерфейсов
2. сложность регрессивного тестирования

## Т-образная стратегия
Описание: Сначала строится очень поверхностный каркас системы из пустых папок и интерфейсов с заглушками, затем начинается детальная реализация. Применяется в разработке платформ, фреймворков и видеоигр.

Преимущества:
1. технологическая независимость
2. масштабирование

Недостатки
1. проблема согласованности данных
2. сетевые задержки
3. сложность локализации ошибок
