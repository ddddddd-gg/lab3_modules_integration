# Анализ метрик тестирования проекта «Система обработки матриц»

## 1. Покрытие кода
- **Формула:** `(Количество выполненных строк и ветвлений / Общее число строк и ветвлений) × 100%`
- **Фактическое значение:** **96%** (по модулям: `src/matrix_processing.py` — 96%, `src/matrix_output.py` — 97%, `src/main.py` — 95%).
- **Целевой порог (Вариант 19):** не менее **75%**.
- **Вывод:** целевой показатель перевыполнен на 21%. Непокрытыми остались только системные точки входа `if __name__ == '__main__':`, не вызываемые при импорте модулей в тестовом окружении.

## 2. Плотность дефектов
- **Формула:** `Общее число найденных дефектов / Объём кода в тысячах строк (KLOC)`
- **Исходные данные:**
  - Суммарный объём исходного кода в каталоге `src/` (`matrix_processing.py`, `matrix_output.py`, `main.py`): **~205 строк кода (0.205 KLOC)**.
  - Общее количество выявленных и устранённых дефектов: **3** (деление на ноль при передаче `[]`, возврат кода `415` вместо `400` при пустом JSON, неверный отступ `return` в функции `size_input()`).
- **Расчёт:** `3 / 0.205 ≈ 14.63 дефекта на 1000 строк кода (KLOC)`.
- **Вывод:** все обнаруженные дефекты относились к обработке граничных и некорректных входных данных и были полностью устранены до фиксации релиза `v1.1.0`.

## 3. Среднее время нахождения дефекта
- **Формула:** `Общее время выполнения тестирования / Количество обнаруженных дефектов`
- **Расчёт:** разработка и первичный прогон автоматизированных тестов заняли **30 минут**, в ходе которых было выявлено **3 дефекта**. Среднее время нахождения одного дефекта составило `30 / 3 = 10 минут`.
- **Вывод:** применение фреймворка `pytest` в сочетании с методом причинно-следственных связей позволило оперативно обнаружить все логические ошибки на этапе модульного тестирования без длительной ручной отладки.
