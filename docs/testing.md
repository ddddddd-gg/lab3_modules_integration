# Документация тестирования проекта «Система обработки матриц»

## 1. План тестирования
- **Предметная область:** Система обработки матриц (сквозной проект ЛР №1–ЛР №3).
- **Вариант:** №19 (метод проектирования тестов — анализ причинно-следственных связей, инструмент — `pytest`, целевое покрытие — не менее 75%).
- **Уровень сложности:** Уровень 3 (высокий).
- **Объект тестирования:** все программные модули проекта (`src/matrix_processing.py`, `src/matrix_output.py`, `src/main.py`).
- **Виды тестирования:** модульное (unit), интеграционное и регрессионное тестирование.
- **Методы проектирования тестов:**
  - «Чёрный ящик»: анализ причинно-следственных связей (построение таблиц решений).
  - «Белый ящик»: покрытие решений, покрытие условий, комбинаторное покрытие условий.
- **Критерии приёмки:** успешное прохождение 100% тестов (18 из 18), покрытие кода и ветвлений не ниже 75%, отсутствие замечаний линтера `flake8`.


## 2. Описание тестовых сценариев

### 2.1. Модульное тестирование («Чёрный ящик» — анализ причинно-следственных связей)
- **`tests/test_processing.py` (4 теста):** проверка реакций REST-сервиса `/transpose` на комбинации входных причин: передача валидной матрицы `2×3` (`test_transpose_success`), пустого списка `[]` (`test_transpose_empty_matrix`), словаря без ключа `matrix` (`test_transpose_missing_key`) и пустого тела запроса `None` (`test_transpose_none_json`).
- **`tests/test_output.py` (4 базовых теста):** проверка аналогичных комбинаций входных причин для REST-сервиса `/output` (`test_output_success`, `test_output_empty_matrix`, `test_output_missing_key`, `test_output_none_json`).
- **`tests/test_main.py` (5 базовых тестов):** проверка валидации пользовательского ввода размерности (`test_valid_number_input`, `test_invalid_number_input`), обработки ответов сервера (`test_server_status_200`, `test_missing_module_error`) и полного цикла работы управляющей функции (`test_main_full_cycle`).

### 2.2. Модульное тестирование («Белый ящик»)
- **`test_output_dynamic_space` (`tests/test_output.py`):** проверка ветки `False` условия `if n > 1:` при форматировании однострочной матрицы (`n == 1`).
- **`test_main_full_cycle_repeat` (`tests/test_main.py`):** покрытие ветки повторного запуска управляющего цикла при вводе `'Д'`.

### 2.3. Интеграционное тестирование
- **`test_integration` (`tests/test_integration.py`):** проверка сквозного взаимодействия всех трёх модулей: ввод матрицы `2×3` в `main.py` → отправка запроса на `/transpose` (`matrix_processing.py`) → передача транспонированной матрицы `3×2` на `/output` (`matrix_output.py`) → вывод отформатированной таблицы в консоль.

### 2.4. Регрессионное тестирование
- **`tests/test_regression.py` (2 теста):** повторная проверка устранённых дефектов для защиты от их возврата при дальнейших изменениях кода:
  - `test_none_json` — возврат кода `400` вместо `415` при пустом теле запроса (`json=None`) для сервисов `/transpose` и `/output`;
  - `test_size_input` — отказ функции `size_input()` принимать `0` и отрицательные числа.

## 4. Выявленные и исправленные дефекты (Баг-репорты)


### Баг-репорт 1
- **Заголовок:** Возврат кода `415 Unsupported Media Type` вместо `400 Bad Request` при отсутствии JSON-тела (`json=None`).
- **Описание:** Вызов `request.get_json()` без параметров требует наличия заголовка `Content-Type: application/json` и при пустом теле запроса прерывает обработку с кодом `415`.
- **Шаги воспроизведения:**
  1. Отправить POST-запрос на `/transpose` или `/output` без тела запроса (`json=None`).
  2. Проверить код ответа сервера (`test_none_json`).
- **Ожидаемое поведение:** Код `400 Bad Request`.
- **Фактическое поведение:** Код `415 Unsupported Media Type`.
- **Тяжесть:** средняя. **Приоритет:** средний. **Статус:** исправлено (`request.get_json(silent=True)`).

### Баг-репорт 2
- **Заголовок:** Функция `size_input()` в модуле `main.py` принимает неположительные числа (`0`, `-1`) как корректную размерность матрицы.
- **Описание:** Из-за логической ошибки в уровне вложенности оператора `return x` цикл валидации `while x < 1:` прерывается на первой итерации даже при срабатывании условия `if x < 1:`.
- **Шаги воспроизведения:**
  1. Вызвать функцию `size_input()`.
  2. Ввести `-1` или `0` (`test_size_input`).
- **Ожидаемое поведение:** Вывод предупреждения «Ввод должен быть больше 0!» и повторный запрос корректного числа.
- **Фактическое поведение:** Предупреждение выводится, но функция завершается и возвращает введённое некорректное число.
- **Тяжесть:** высокая. **Приоритет:** высокий. **Статус:** исправлено (оператор `return x` перенесён внутрь ветки `else:`).
