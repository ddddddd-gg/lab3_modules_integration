# Сравнительный анализ методов тестирования программного обеспечения

## 1. Обзор и сравнение методов тестирования

### 1. Анализ причинно-следственных связей *(основной метод Варианта 19)*
- **Подход:** «чёрный ящик».
- **Преимущества:** системно связывает комбинации входных условий с реакциями программы, отсекает логически невозможные комбинации и помогает выявлять противоречия в требованиях.
- **Недостатки:** высокая трудоёмкость построения таблиц решений при большом числе входных параметров (количество комбинаций растёт как $2^n$).
- **Рекомендации по применению:** использовать для модулей с развитой логикой ветвлений и несколькими взаимозависимыми входными параметрами (например, REST API и валидаторы запросов).

### 2. Эквивалентное разбиение и анализ граничных значений
- **Подход:** «чёрный ящик».
- **Преимущества:** резко сокращает число избыточных тестов при высокой вероятности обнаружения ошибок на границах диапазонов (например, `0`, `-1`, пустой список `[]`).
- **Недостатки:** не учитывает внутреннюю структуру кода и сложные комбинации нескольких условий одновременно.
- **Рекомендации по применению:** применять как базовый метод для любых функций пользовательского ввода, числовых расчётов и работы с массивами.

### 3. Покрытие операторов, решений и условий
- **Подход:** «белый ящик».
- **Преимущества:** гарантирует выполнение всех веток `if/else` и комбинаций логических операторов (`and`/`or`), которые могли остаться нетронутыми при тестировании только по спецификации.
- **Недостатки:** не выявляет отсутствующую функциональность (если разработчик забыл написать нужную проверку в коде, метрика покрытия этого не покажет).
- **Рекомендации по применению:** использовать как дополнение после тестов «чёрного ящика» для поиска «мёртвых» участков кода и доведения покрытия ветвлений до целевого порога (75–95%).

### 4. Интеграционное тестирование
- **Подход:** «серый ящик».
- **Преимущества:** выявляет ошибки стыковки между отдельными сервисами и модулями (несовпадение форматов JSON, сетевых портов, типов данных `int`/`float`).
- **Недостатки:** сложнее локализовать точную строку сбоя при падении сквозного сценария; более долгое время выполнения.
- **Рекомендации по применению:** обязательно проводить после завершения модульного тестирования для проверки ключевых пользовательских сценариев от начала до конца.

### 5. Регрессионное тестирование
- **Подход:** автоматизированный (CI/CD).
- **Преимущества:** гарантирует, что новые правки и рефакторинг не сломали уже работающий функционал и не вернули ранее исправленные баги.
- **Недостатки:** требует регулярной актуализации тестового набора при изменении требований к системе.
- **Рекомендации по применению:** включать в обязательный пайплайн CI/CD для автоматического запуска при каждом коммите или изменении кода.


## 2. Рекомендации по применению
Для распределённых систем обработки данных (аналогичных «Системе обработки матриц») оптимальной является **комбинированная стратегия**: проектирование основного ядра тестов методом анализа причинно-следственных связей («чёрный ящик») с последующим дополнением тестами «белого ящика» для закрытия редких веток условий и обязательным закреплением исправленных дефектов в регрессионном наборе.
